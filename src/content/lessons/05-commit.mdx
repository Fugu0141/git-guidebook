## 今回の場面

編集した内容を「練習メモを追加した変更」というひとまとまりの履歴にします。後から見た人が目的を理解できるよう、Commitメッセージには結果ではなく変更の内容を書きます。

## 今回できるようになること

- Commit前に差分と対象Branchを確認できる
- 変更内容が伝わるCommitメッセージを書ける
- CommitはGitHubへの送信ではないと説明できる

## まず簡単に説明

Commitは、選んだ変更を説明文と一緒に、端末内のローカルリポジトリへ記録する操作です。写真のシャッターのように、意味のある区切りで履歴を1つ作ります。

## もう少し正確に

GitHub Desktopでは、チェックした変更をCommit対象として選び、Summaryを付けます。Commitが成功するとローカルBranchが新しいCommitへ進みますが、GitHub上のBranchはまだ進みません。

<OptionalDetails summary="SummaryとDescriptionの使い分け">
  Summaryは履歴一覧で最初に見える短い説明です。何を変えたかを簡潔に書きます。Descriptionには、なぜ必要か、注意点は何かなどを補足できます。
</OptionalDetails>

## 操作前

READMEの変更は作業フォルダにあります。ローカルリポジトリにもGitHubにも、新しい履歴はまだありません。

## 一緒に操作

1. GitHub Desktopの **Changes** で `README.md` の差分をもう一度確認します。
2. 左下の **Summary (required)** に `Add practice note` と入力します。
3. **Description** は今回は空でも構いません。理由や補足が必要なときに使います。
4. ボタンが **Commit to main** になっていることを確認します。
5. **Commit to main** を選びます。
6. Changesが空になり、上部に **Push origin** が表示されることを確認します。

## 内部で起きたこと

選択した変更から新しいCommitが作られ、`main` のローカル履歴が1つ進みました。GitHub Desktopが「Push origin」を示すのは、まだGitHubへ送っていないCommitがあるからです。

## 対応するGitコマンド

<CommandGuide
  directory="git-guidebook-practice作業フォルダの中で実行します。"
  prerequisite="README.mdの差分を確認済みで、mainにいること。"
  effect="git addでREADMEを次のCommit対象に選び、git commitでローカルmainへ履歴を1つ作ります。GitHubは変わりません。"
  desktopEquivalent="Changesのチェックをオンにし、Summaryを書いてCommit to mainを選ぶ操作です。"
  output="1 file changedと変更行数が表示され、git statusでworking tree cleanなら記録済みです。"
  firstCheck="nothing to commitなら保存済み差分とgit statusを、Author identity unknownならGitの名前・メール設定を確認します。"
>
  ```bash git add README.md git commit -m "Add practice note" ```
</CommandGuide>

## できるようになったこと

- 差分、対象ファイル、Branch、Summaryを確認してCommitできる
- Commit後はローカルmainだけがGitHubより進むと判断できる
- CommitとGitHubへの送信を別の操作として説明できる

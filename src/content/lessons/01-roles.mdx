## 今回の場面

GitHub DesktopでCommitボタンを押したのに、ブラウザでGitHubを開くと変更が見つからない。初心者がよく出会う場面です。これは失敗とは限りません。Git、GitHub、GitHub Desktopの役割と、3つの場所を混同していると起きる迷いです。

今回はまだ練習用リポジトリを作りません。道具を開いて「いま見ているのは端末側か、GitHub側か」を見分ける練習をします。

## 今回できるようになること

- Git、GitHub、GitHub Desktopの役割を自分の言葉で説明できる
- 作業フォルダ、ローカルリポジトリ、GitHub上のリモートリポジトリを区別できる
- CommitとPushが変える場所を正しく選べる

## まず簡単に説明

| 名前           | ひとことで言うと                     | 主に動く場所 |
| -------------- | ------------------------------------ | ------------ |
| Git            | ファイルの変更履歴を管理する仕組み   | 自分の端末   |
| GitHub         | リポジトリを置いて共有できるサービス | Web上        |
| GitHub Desktop | Gitの状態確認と操作を行う画面アプリ  | 自分の端末   |

<Callout type="tip" title="GitHub Desktopは中継役">
  GitHub
  Desktopは、作業フォルダの差分やローカルの履歴を見せ、ボタン操作をGitへ伝えます。必要なときはGitHubとも通信しますが、GitそのものでもGitHubそのものでもありません。
</Callout>

## もう少し正確に

「ローカル」は自分の端末側、「リモート」はネットワーク上の相手側を表します。このコースでは、GitHub上のリポジトリをリモートリポジトリとして使います。

<OptionalDetails summary="リポジトリには何が入る？">
  リポジトリは、プロジェクトのファイルとGitの履歴を管理する単位です。端末側では作業フォルダの中にGitが使う隠し領域があり、そこがローカルリポジトリの履歴を支えます。GitHub上のリポジトリには、PushされていないCommitや作業中の未Commit変更はありません。
</OptionalDetails>

## 操作前

GitHub Desktopをインストールしてサインインしていても、それだけでは今回の練習用リポジトリや履歴は作られていません。

## 一緒に操作

1. GitHub Desktopを開きます。まだ教材用リポジトリがなくても構いません。
2. 画面上部にリポジトリ名やCurrent Branchを表示する場所があることを確認します。これは端末側で現在選んでいるローカルリポジトリとBranchの情報です。
3. ブラウザで [GitHub](https://github.com/) を開きます。こちらはGitHubというWebサービスの画面です。
4. 次の文を、画面を指しながら声に出すかメモします。
   - Gitは、端末内を中心に変更履歴を管理する仕組み。
   - GitHubは、リモートリポジトリを置いて共有するWebサービス。
   - GitHub Desktopは、Gitの状態を見て操作するためのアプリ。
5. 「Commitはローカルを変える」「PushはGitHub上のリモートを進める」と書き足します。

サインインしていない場合は、今回は画面の違いを確認するだけで構いません。アカウント作成や認証情報の入力を急いで進める必要はありません。

## 自分でやってみる

  次の出来事を「作業フォルダ」「ローカルリポジトリ」「GitHub上のリモートリポジトリ」のどこで起きるか分類してください。

1. エディターでREADMEを保存する
2. GitHub DesktopでCommitする
3. GitHub DesktopでPushする
4. ブラウザでGitHub上のREADMEを見る

答えは順に、作業フォルダ、ローカルリポジトリ、リモートリポジトリ、リモートリポジトリ、作業フォルダと記録済み内容の比較です。

## できるようになったこと

- Git、GitHub、GitHub Desktopを別の役割として説明できる
- 作業フォルダ、ローカルリポジトリ、GitHub上のリモートリポジトリを区別できる
